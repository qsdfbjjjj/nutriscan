# NutriScan — сканер продуктов

Индивидуальный проект по курсу мобильной разработки на Flutter.
Тема №24: **Food Scanner**. Автор: Избасар Даниял.

## Цель

Помочь пользователю быстро понять, что он покупает и ест. По штрихкоду или названию
приложение показывает состав, калорийность, БЖУ, аллергены и оценку Nutri-Score.
Продукты сохраняются в историю и избранное и доступны без интернета.

## Целевая аудитория

- Люди, которые следят за питанием и считают калории.
- Аллергики и те, кто избегает определённых ингредиентов (глютен, лактоза, орехи).
- Спортсмены, которым важны белки, жиры и углеводы.
- Покупатели, которые хотят сравнивать продукты прямо в магазине.

## Архитектура

Три слоя, зависимости направлены внутрь — к домену:

```
lib/
├── core/            общее: DI, роутер, тема, строки, ошибки, виджеты
├── domain/          сущности (Product, AppUser) и интерфейсы репозиториев
├── data/            реализация: API, Hive, SharedPreferences, репозитории
└── presentation/    экраны, BLoC/Cubit, Provider
```

- **Domain** ничего не знает про Flutter, сеть и базу данных.
- **Data** реализует интерфейсы домена (`ProductRepositoryImpl implements ProductRepository`).
- **Presentation** работает только с интерфейсами репозиториев.
- **Repository** — единая точка доступа к данным: экрану всё равно, пришли они из сети или из кэша.
- **Dependency Injection** — `get_it` (`lib/core/di/injector.dart`): все зависимости собираются
  в одном месте и передаются через конструкторы, поэтому в тестах их легко подменить моками.

## Управление состоянием

### Почему Provider + BLoC

| Где | Что | Почему |
|---|---|---|
| Тема и язык | **Provider** (`SettingsProvider`) | Два значения без асинхронных состояний — BLoC здесь был бы избыточен |
| Поиск | **BLoC** (`SearchBloc`) | Много событий (ввод, следующая страница, обновление), нужен debounce и отмена старых запросов |
| Карточка продукта, избранное, история, вход | **Cubit** | Простые действия без потока событий — Cubit короче, чем BLoC |

BLoC выбран вместо Riverpod, потому что он явно разделяет события и состояния: по коду видно,
что произошло и к какому состоянию это привело. Состояния легко тестировать (`bloc_test`).

### Сравнение подходов (неделя 3)

Одна и та же функция «избранное» реализована тремя способами — экран «Настройки → Демо».

| | setState | InheritedWidget | Provider |
|---|---|---|---|
| Где состояние | Внутри одного StatefulWidget | Наверху дерева | В ChangeNotifier |
| Доступ из потомков | Только через параметры конструкторов | `Scope.of(context)` | `context.watch / read / select` |
| Кода | Меньше всего | Много шаблонного | Немного |
| Перерисовка | Весь виджет целиком | Только зависимые | Только подписчики, `select` — точечно |
| Когда применять | Локальное состояние одного экрана (поле ввода, анимация) | Когда нельзя тянуть пакеты; основа Provider | Общее состояние нескольких экранов |

## Сеть: REST API

Источник данных — открытый API [Open Food Facts](https://openfoodfacts.github.io/openfoodfacts-server/api/), ключ не нужен.

- `GET /api/v2/product/{barcode}` — продукт по штрихкоду;
- `GET /cgi/search.pl?search_terms=…&page=…` — поиск с пагинацией.

Клиент — `dio` с таймаутами (10 с на соединение, 20 с на ответ). Ошибки переводятся в типы
`NetworkFailure`, `NotFoundFailure`, `ServerFailure`, и экран показывает понятное сообщение.
Все экраны с данными имеют состояния **loading / success / empty / error**.

JSON разбирается вручную (`ProductModel`), а не через json_serializable: API неоднородный —
числа приходят то числом, то строкой с запятой, оценка бывает `"unknown"`, название лежит
в разных полях. Разбор покрыт тестами.

## Локальное хранение

- **SharedPreferences** — тема, язык, вошедший пользователь.
- **Hive** — кэш продуктов и результатов поиска, избранное, история (до 50 продуктов).
- **Offline-first**: репозиторий сначала идёт в сеть и сохраняет ответ в кэш; если сети нет,
  отдаёт данные из кэша, а экран показывает плашку «Нет сети — показаны сохранённые данные».

## Навигация

`go_router`:
- маршрут с параметром `/product/:barcode`;
- вложенная навигация `StatefulShellRoute` — у каждой вкладки свой стек и сохранённое состояние;
- `redirect` — без входа доступен только `/login`;
- вложенный маршрут `/settings/state-demo`.

**Адаптивность:** на телефоне — нижняя панель `NavigationBar` и список; при ширине от 640 px
(планшет, альбомная ориентация) — боковая `NavigationRail`, списки становятся сеткой,
а карточка продукта — двухколоночной.
